# 交付契約

## 使用時機

在任務完成前啟用，檢查是否已交代使用者需要知道的結果、風險與下一步。

> [!TIP]
> **Minimal 免檢疫例外**：若任務判定為 `Minimal` 車道 (極簡快車道)，**強制豁免**產出以下完整的標準收尾區塊。改以一句話精簡總結完成狀態與耗時即可，以達到最高執行效率。

## 標準收尾

```text
任務追蹤 (Telemetry)
- 工作流路徑 (Routing Path): [例如 Minimal, Standard, Full Orchestrator]
- 各路徑耗時 (Time Spent): [列出各節點/子代理解決問題的耗時]
- 載入的 Skill (Skills Loaded): [列出過程中啟用的 Skill 名稱]

完成狀態
- ...

修改清單
- ...

測試與檢查
- ...

待確認事項
- ...
```

## 規則

- 有修改檔案時列出所有檔案；沒有修改寫「無」。
- 有測試或檢查時列出指令/方式與結果；未執行需說明原因。
- 有失敗、跳過、未確認、需人工判斷的事項，明確列出。
- 不把大量檔案內容貼到回覆中；只列路徑、摘要與結果。
- **所有本機路徑與遠端連結，都必須使用可點擊的 Markdown 格式** (例如：`[檔名](file:///C:/絕對路徑)`)，方便使用者直接點選開啟。
- 本 Skill 負責整理交付回報，不負責判斷成果是否通過內容或風險檢查；需要時另行啟用 `checklist-validator`。
- 若完成同步、commit、push，列出實際成功的動作。

## 高風險附加欄位

涉及設定、同步、刪除、遠端、憑證、資料搬移時，加上：

```text
風險與保護
- ...
```
