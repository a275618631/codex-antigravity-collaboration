# Codex 設定同步規劃_20260611

## 結論

採用 GitHub private repo 作為主同步源。

Google Drive 不作為主同步源，只作為設定備份、災難復原與人工查閱入口；日常更新不從 Drive 覆蓋本機。

## 20260611 更新與封存紀錄

- <span style="color:red">修正：舊版「每台電腦每日自動 pull」已停用；遠端設定拉取必須手動選來源電腦與分類。</span>
- <span style="color:red">修正：舊版只維護單一 `要同步的Codex設定/` 同步包，已改為 `backups/<電腦名稱>/<分類>/` 分類備份。</span>
- 舊流程對比：~~從 GitHub／Drive 混合更新~~ -> 固定從 GitHub `master` pull，再由腳本自動選擇最新來源電腦並套用全部可攜分類（含 `.codex/agents/`）。
- Codex 設定修改後預設只做本機匯出；GitHub Commit／Push／Draft PR 只在使用者主動要求時由 Luna 執行。

## GitHub 優勢

- 適合管理 `AGENTS.md`、`.codex/`、skills、workflows 與同步腳本。
- commit 歷史可回溯。
- 每台電腦可分開備份，避免不同電腦設定互相覆蓋。
- 手動拉取分類可以降低誤套用風險。
- 手動 `commit + push` 前可以 review，降低誤同步機密的風險。

## 備份流程

修改 Codex 設定的電腦先執行本機匯出：

```powershell
.\同步工具\自動備份並推送.ps1
```

不加確認參數時腳本只執行前兩項：

1. 匯出目前電腦的分類備份。
2. 清洗 `config.toml`，排除本機路徑、sandbox、trusted projects、runtime path、plugin cache path。
3. 使用者明確要求 GitHub 上傳時，由 Luna 建立非受保護功能分支。
4. 加上 `-ConfirmPush` 後 Commit 並 Push；不執行 rebase 或 Merge。
5. 需要 PR 時建立或更新 Draft PR。

## 手動拉取流程

其他電腦：

```powershell
git switch master
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category all
```

## 回溯方式

查詢近 1 個月設定變更：

```powershell
git log --since="30 days ago" -- backups 同步工具 使用說明.md 同步規劃.md
```

查看舊版本：

```powershell
git show <commit>:backups/<電腦名稱>/agents-root/AGENTS.md
```

還原指定檔案：

```powershell
git restore --source <commit> -- backups/<電腦名稱>/agents-root/AGENTS.md
```
