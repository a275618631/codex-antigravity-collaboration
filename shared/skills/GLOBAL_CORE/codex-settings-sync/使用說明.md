# Codex 設定同步使用說明

這個資料夾只用來同步 Codex 通用設定，不放專案產物、影片、程式碼成果或 credentials。

## 目的

讓不同電腦使用 Codex 時，採用相同的規則、設定、skills、workflows、execution profiles 與同步流程。

## 來源政策

- GitHub `master` 是 Codex 可攜設定的唯一日常來源與版本真實來源。
- Google Drive 只作備份、災難復原與人工查閱，不參與日常覆蓋或與 GitHub 混合合併。
- 另一台電腦套用設定時，固定先更新 GitHub `master`，再從 GitHub 套用全部可攜分類。

## GitHub 備份結構

新的遠端備份結構以電腦名稱分開，並在每台電腦底下再分分類：

```text
backups/
  <電腦名稱>/
    agents-root/AGENTS.md
    agents-codex/AGENTS.md
    agents/                  # 自訂 agent 設定（例如 research.toml）
    config/config.toml
    execution-profiles/
      sol-auto.config.toml
      luna-manual.config.toml
    skills/
    workflows/
    workflow-definitions/
    sync-tools-and-docs/
    metadata/export-info.txt
```

`要同步的Codex設定/` 是舊版相容同步包，保留作為人工閱讀與過渡用途；分電腦、分分類拉取以 `backups/` 為主。

## 可分開同步的分類

- `agents-root`：`AGENTS.md`
- `agents-codex`：`.codex/AGENTS.md`
- `agents`：`.codex/agents/` 自訂 agent 設定
- `config`：非機密 `config.toml`
- `execution-profiles`：可攜的 `sol-auto.config.toml` 與 `luna-manual.config.toml`
- `skills`：自訂 skills，排除 `.system`
- `workflows`：工作流與可重複 SOP
- `workflow-definitions`：Codex 工作流定義與交付流程
- `sync-tools-and-docs`：同步腳本與說明文件

環境盤點是獨立階段，不會寫回可直接套用的 `config.toml`：

- `同步工具/匯出-Codex環境清單.ps1`：唯讀盤點 MCP、CLI、外部服務與自訂 skills。
- `schemas/codex-environment-manifest.schema.json`：環境清單資料契約。
- `環境清單/current/`：JSON、YAML、重建清單與驗證報告；`history/` 只保留本機歷史。
- `文件/Codex環境清單使用說明.md`：安裝、登入、連線驗證與來源／目標比較流程。

來源電腦產生清單：

```powershell
.\同步工具\匯出-Codex環境清單.ps1
.\同步工具\測試-Codex環境清單.ps1
```

環境清單只描述重建步驟，不攜帶 MCP env 值、API Key、Token、Cookie、OAuth 或登入狀態。

## 不同步內容

- `.env`
- OAuth / Notion / Google / GitHub 登入狀態
- tokens、credentials、auth.json
- 本機 plugin cache 狀態
- OS 工作排程器 / macOS launchd
- 本機路徑、沙盒權限、信任專案狀態
- session DB、暫存、cache
- Codex 內建 `.system` skills
- 外掛 cache 或 marketplace cache
- 影片
- 專案產出程式碼
- 任務輸出資料

## 本機匯出與 GitHub 備份

修改 Codex 設定後先匯出到本機同步 repo，不會自動上傳：

```powershell
.\同步工具\自動備份並推送.ps1
```

只有使用者主動要求上傳 GitHub 時，才由 Luna 在非受保護功能分支執行：

```powershell
.\同步工具\自動備份並推送.ps1 -Branch <功能分支> -ConfirmPush
```

腳本不會 rebase、Merge 或直接推送 `main`／`master`。合併由使用者明確授權後另行處理。分類匯出入口是：

```powershell
.\同步工具\匯出目前設定到同步包.ps1
```

## Codex 口令

在任何 Codex 對話中，可使用以下口令：

- 「同步設定」或「更新設定」：匯出本機目前 Codex 設定並檢查差異，不自動上傳。
- 「上傳 Codex 設定到 GitHub」：由 Luna 在非受保護功能分支 Commit、Push 並建立／更新 Draft PR，不 Merge。
- 「套用 Codex 設定」、「更新 Codex 設定」、「更新最新設定」、「參考 GitHub 更新」：視為從 GitHub `master` 套用最新可攜設定；先確認同步 repo 工作區乾淨，再 pull，最後自動選擇最新來源電腦並套用全部分類，不使用聯集模式。
- 上述口令是「從 GitHub 更新本機」，不會建立或執行備份腳本；只使用既有同步 repo 與既有套用工具。若另一台電腦尚未有同步 repo，先取得 `a275618631/codex-settings-sync` 的 clone；路徑或是否要覆蓋本機設定不明確時才詢問。
- 「同步設定」：若未說明方向，預設仍只做本機檢查；涉及上傳、拉取或覆蓋時主動詢問。
- 「同步」或「更新」：若沒有 Codex／設定／GitHub 語意，才詢問要上傳本機設定、拉取最新設定，還是只檢查差異。

Codex 設定不建立每日自動上傳。可使用只提醒或只做本機匯出的 Automation；Commit／Push／PR 只在使用者主動要求時執行。

Automation 含本機 thread id 與本機 Codex app 狀態，不建議原樣跨電腦同步。其他電腦要使用相同提醒時，請在該電腦的 Codex app 重新建立或更新同名 automation。

## 手動拉取

新電腦或其他電腦從 GitHub 更新時，固定使用 `master`；來源電腦會依 GitHub 備份中的最新 `export-info.txt` 自動選擇，不必手動輸入來源名稱：

```powershell
git switch master
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category all
```

常用範例：

```powershell
# 只拉 AGENTS.md（來源電腦自動選擇）
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category agents-root

# 只拉自訂 skills，並與本機內容取聯集
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category skills -Union

# 只拉 workflow
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category workflows -Union

# 套用 Sol Auto／Luna execution profiles（不使用 Union）
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category execution-profiles

# 拉全部分類
.\同步工具\手動拉取分類設定.ps1 -Pull -Branch master -Category all
```

完整套用使用不加 `-Union` 的 `all`；`-Union` 只適合明確要保留本機額外內容的部分分類更新。若同步 repo 有未提交變更，腳本會停止，避免 GitHub 更新覆蓋本機同步資料。

## 聯集規則

分電腦備份的目的，是允許不同電腦上傳不同版本。拉取時有兩種模式：

- 不加 `-Union`：用 GitHub `master` 中最新來源電腦的分類覆蓋同名目標檔案，適合完整套用。
- 加 `-Union`：目錄取聯集；同名文字檔則保留本機內容，並把遠端檔案中本機沒有的文字行附加到檔尾。

這裡的聯集不是只看檔名。skills、workflows 會合併檔案集合；同名文字檔會合併內容。若遇到非文字檔且內容衝突，腳本會保留遠端副本為 `*.remote-conflict.*`。

## Windows 與 macOS

- Windows 使用 `.ps1`。
- macOS 使用 `.sh`。
- 含中文路徑時，Windows 建議使用 PowerShell 7 執行 `.ps1` 腳本。
- `每日自動同步.ps1` 與 `.sh` 已改成提示腳本，不再自動拉取遠端設定。

## GitHub repo 建議

GitHub repo 名稱建議使用英文：

```text
codex-settings-sync
```

原因是遠端 URL、命令列與工作排程對英文名稱較穩定。

本機資料夾與說明文件則使用中文名稱。
