Context（上下文）最小化； 4. 對允許類別進行可逆假名化； 5. 本地還原； 6. 外洩測試。 不建立新的資安 Framework（框架）；優先採用成熟偵測元件與薄型本地 Policy layer（政策層）。 ### 本地模型作為私密／離線處理路徑 — 已規劃整合 本地模型預計支援： - Restricted（限制）或離線任務； - 網路受限環境； - 敏感內容的語意分類； - 特定低風險自動化。 它應該補充確定性 Policy（政策），而不是取代它。 ## 探索中的方向 ### 跨電腦協調 先從多台電腦共用 Workspace（工作區）開始。 只有任務真的需要明確的跨主機 request / result（請求／結果）傳輸時，才進入專門的 Agent interoperability layer（Agent 互通層）。 [A2A](https://github.com/a2aproject/A2A) 是一個在自行發明 Agent-to-Agent Protocol（Agent 對 Agent 通訊協定）前，值得優先評估的既有標準。 ### 薄型 Broker（任務仲介服務） Broker **不是目前架構的一部分**。 只有實際出現以下需求時才引入： - Lease（租約）； - Heartbeat / Liveness（心跳／存活確認）； - Retry（失敗重試）； - Distributed task state（分散式任務狀態）； - Concurrency ownership（併發寫入所有權）； - Real-time scheduling（即時排程）。 ## 從路線圖升級為「已實作」的條件 一個路線圖項目只有同時符合以下條件，才可以標記為 **已實作**： 1. 有可以執行或可以直接觀察的實作； 2. 已進行 End-to-End（端到端）測試； 3. 失敗案例有被測試； 4. Security / Permission（資安／權限）行為有文件； 5. 有 Rollback（回復）或安全停用方式； 6. 公開文案與實際證據一致。 ## 哪些事情不足以成為「新增元件」的理由 不要只是因為以下情況就加入新的基礎設施： - 有多個模型； - 有多個 Agent； - 架構圖畫一個中央 Server（伺服器）看起來比較整齊； - 某個 Framework 很熱門； - 共用資料夾看起來不夠「高級」。 這個專案應該始終： > **比它要解決的問題更小。** {% endcapture %} {{ zh | markdownify }}
